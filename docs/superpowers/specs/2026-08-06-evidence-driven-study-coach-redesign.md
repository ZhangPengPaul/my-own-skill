# 上海高中学习教练：证据驱动学习闭环重设计

日期：2026-08-06

本设计经用户逐节确认。它在冲突处取代
`2026-08-06-shanghai-high-school-study-coach-design.md`，并重新定义
`shanghai-high-school-study-coach` 的核心职责。

## 1. 核心目标

Skill 的首要目标是辅助学生学习，并在学习过程中根据真实作答识别薄弱点，进行
针对性强化，再用新的学生表现验证是否改善。

```text
学生作答
  -> 提取证据
  -> 定位并验证薄弱点
  -> 针对性讲解和练习
  -> 变式验证
  -> 延迟复测
  -> 更新掌握状态和后续计划
```

第一阶段支持语文、数学、英语、政治、历史、地理。物理、化学、生物可以在后续
阶段复用同一学习闭环，但不属于本次重设计的实现和验收范围。

### 1.1 非目标

- 不承担上海考试政策、考试日程、成绩换算或官方规则查询。
- 不加载或访问上海市教育委员会、上海市教育考试院等政策来源。
- 不在缺少教师答案或明确评分标准时编造评分点或分数。
- 不把 Codex 给出的讲解当成学生已经掌握的证据。
- 不保证分数、排名、录取或任何考试结果。
- 不自动提交作业，不冒充学生完成对外提交。

“上海高中生”只限定目标学生群体、年级环境和首期学科，不为 Skill 引入考试政策
职责。

## 2. 架构

采用“一个核心学习教练 + 六科学科参考”的结构。

### 2.1 核心学习教练

`SKILL.md` 统一负责：

- 判断当前学科、任务模式和学习目标。
- 区分不持久化临时答疑和跨会话学习。
- 在“先尝试、分层提示”和“直接完整解析”之间路由。
- 从学生真实作答中提取证据。
- 区分学科内容薄弱点和能力或错误模式。
- 安排当场强化、变式验证和延迟复测。
- 根据事实记录对账掌握状态和学习计划。

统一支持六种任务模式：诊断当前表现的 `assessment`、讲解知识或方法的
`explanation`、针对性练习的 `practice`、依据明确答案或教师标准批改的
`grading`、复盘已完成任务的 `review`，以及安排学习和复测的 `planning`。
同一会话可以切换模式，但持久化记录必须保存切换及其依据。

### 2.2 学科参考

六个学科参考分别负责：

- 固定的学科模块目录。
- 动态知识单元的归类和名称归一化规则。
- 学科特有的诊断维度。
- 详细讲解的必要组成。
- 适合该学科的强化练习、变式和迁移验证方式。

每次只加载当前学科参考，不加载其他学科内容。学科参考不保存考试政策或网站
链接，也不保存完整教材、商业题库或答案库。

### 2.3 目录目标

```text
skills/shanghai-high-school-study-coach/
|-- SKILL.md
|-- agents/
|   `-- openai.yaml
|-- references/
|   |-- chinese.md
|   |-- mathematics.md
|   |-- english.md
|   |-- politics.md
|   |-- history.md
|   `-- geography.md
|-- scripts/
|   |-- init_student.py
|   |-- validate_student_data.py
|   |-- commit_learning_state.py
|   `-- summarize_progress.py
`-- assets/
    `-- student-workspace-template/
```

初始化完成后，`commit_learning_state.py` 是事实对账和状态更新的唯一写入口。
教学判断仍由 Skill 完成；脚本只执行结构校验、确定性计算和安全写入。

## 3. 学科内容模型

采用混合分类，而不是提前维护六科完整知识图谱，也不允许完全自由的标签。

```text
学科 -> 固定模块 -> 动态知识单元
```

固定模块由各学科参考维护。动态知识单元根据学生教材、教师材料和当前任务创建，
保存稳定 `unit_id`、规范名称和别名。后续会话优先匹配现有规范名称；不能可靠匹配
时创建待归一化项，不静默合并两个可能不同的知识单元。

各学科的内容类型不同：

- 语文：语言积累、文言知识、文学文化知识、文本结构和表达手法等。
- 数学：概念、性质、公式、定理和适用条件等。
- 英语：词汇、搭配、语法、句型和语篇结构等。
- 政治：核心概念、原理、概念关系和适用情境等。
- 历史：史实、时间线、阶段特征、因果关系和史料背景等。
- 地理：概念、空间分布、过程、规律、影响因素和区域特征等。

这些列表用于说明类型，不要求每次任务加载完整目录。

## 4. 两类薄弱点

### 4.1 学科内容掌握

每个知识单元采用以下状态：

```text
unassessed
  -> suspected_gap
  -> confirmed_gap
  -> strengthening
  -> provisionally_mastered
  -> stable
  -> transferable
```

- `suspected_gap`：单次错误或学生自述，只能作为待验证线索。
- `confirmed_gap`：追问或最小诊断任务再次暴露同一内容问题。
- `strengthening`：已经完成讲解或订正，但尚无独立迁移证据。
- `provisionally_mastered`：独立完成当场变式，当前可以正确使用。
- `stable`：在延迟、无提示复测中仍能独立完成。
- `transferable`：能在新的表示或情境中独立完成并解释方法。

新证据与旧判断冲突时允许降级。状态不是单向成就，也不根据练习数量自动提升。

### 4.2 能力与错误模式

另行跟踪审题、信息提取、方法选择、推理、计算、记忆、表达和无依据推断等模式：

```text
observed_once -> recurring -> improving -> controlled
```

一次计算或审题失误不自动降低相关知识单元的掌握状态。只有诊断证据表明学生不理解
相关内容时，才建立内容薄弱点。

## 5. 学生表现证据

状态变化只能引用已经完成的结构化学生表现事实。每条事实至少包含：

- 唯一 `evidence_id` 和稳定 `session_id`。
- 学科、固定模块、知识单元和任务模式。
- 题目或任务标识及材料来源描述。
- 学生实际回答、步骤或作品。
- 正确性判断和第一个实质错误。
- 使用过的提示级别。
- 内容薄弱点或能力错误模式分类。
- 证据类型：初次作答、诊断、订正、变式或延迟复测。
- 完成状态和剩余不确定性。

以下内容不是掌握证据：

- Codex 生成的答案或讲解。
- 学生只说“懂了”但没有后续表现。
- 不完整、不可辨认或学科不匹配的记录。
- 缺少学生作答、提示级别或唯一标识的文件。

重复 `evidence_id` 或 `session_id` 必须报告冲突，不重复计数。

## 6. 单次学习会话

### 6.1 公共入口

1. 确认或可靠推断学科、任务模式、可用时间和当前目标。
2. 判断文字、图片或 PDF 是否足以支持诊断；关键内容不清晰时暂停结论。
3. 加载当前学科参考，识别相关模块和候选知识单元。
4. 根据学生请求选择学习引导路径或直接解析路径。

学习内容先对齐学生正在使用的教材、教师讲义和教师明确要求，再使用通用学科知识。
教师材料与可验证的学科事实冲突时明确指出，不静默覆盖，也不扩展为考试政策查询。
批改缺少明确答案或教师标准时，可以验证推理和提供改进意见，但不输出虚构分数。

### 6.2 学习引导路径

1. 询问并保留学生已经完成的步骤。
2. 按题意、已知、目标、方法、推导、计算、表达和结果条件检查表现。
3. 找到第一个实质错误或卡点，不只比较最终答案。
4. 按“定位卡点 -> 回忆知识 -> 提示关键中间量 -> 建议下一步”逐层提示。
5. 用追问或最小诊断任务区分内容薄弱和错误模式。
6. 只补当前缺失内容，不重复讲学生已经表现出掌握的部分。
7. 进入针对性强化和验证。

### 6.3 直接解析路径

学生明确要求答案时立即提供完整解析，不强制先作答。完整解析必须包含：

- 条件和目标整理。
- 方法选择理由。
- 关键知识及适用条件。
- 完整过程。
- 容易出错的位置。
- 结果或结论验证。

解析结束后提供一个简短理解检查或最小变式。解析本身不改变掌握状态；学生完成
理解检查后才能形成新的表现证据。

## 7. 针对性强化

确认薄弱点后执行两阶段强化。

### 7.1 当场最小强化

1. 补充当前缺失的最小前置内容或方法。
2. 完成一道同类订正题。
3. 完成一道改变数字、条件、材料或表示方式的轻度变式。
4. 记录学生实际表现和提示程度。

变式仍失败时向前追溯更基础的知识单元。独立完成时标记
`provisionally_mastered`，停止无效重复刷题。

### 7.2 延迟复测

持久化会话为当前掌握的知识单元安排无提示延迟复测。复测通过后才标记 `stable`；
新的情境中独立完成并解释方法后才标记 `transferable`。

临时会话可以建议后续复测，但不创建记录、计划或状态。

## 8. 优先级和计划

多个薄弱点按以下因素排序：

1. 对后续学习的前置影响。
2. 证据强度，已确认高于待确认。
3. 跨任务重复出现的程度。
4. 学生目标、当前教材和教师进度。
5. 是否已经到达延迟复测时间。
6. 当前可用学习时间。

每次计划最多突出一个主要内容薄弱点、一个必要前置单元、一个高频能力或错误模式，
再加入已经到期的延迟复测。教师明确要求和学生当前目标优先于自动排序。

进度摘要展示新发现的待确认薄弱点、已确认薄弱点、强化中项目、到期复测、稳定或
可迁移内容，以及每项判断对应的证据。摘要不生成猜测分数。

## 9. 学生工作区和持久化

临时会话不要求学生 ID，不创建目录或文件，不复制材料，不读写状态。

跨会话学习必须先取得创建工作区的明确同意，并只使用不透明学生 ID。建议的工作区：

```text
student-workspaces/<student-id>/
|-- profile.md
|-- state.json
|-- sessions/
|   `-- <session-id>.json
|-- plan-items/
|   `-- <item-id>.json
|-- summaries/
|   `-- current.md
`-- materials/
```

完整的 `sessions/` 和 `plan-items/` 记录是事实来源；`state.json` 和摘要是派生结果。
完成的事实记录不可就地修改。需要纠正时新增带有被替代记录 ID 的事实，保留审计链。
材料只在用户明确要求时保存。

## 10. 安全状态提交

持久化实现必须满足：

1. 工作区根目录解析一次并绑定目录描述符。
2. 对必需子目录和文件使用 `lstat`、目录描述符相对访问和 `O_NOFOLLOW`，拒绝符号
   链接和越界路径。
3. 使用覆盖“读取事实 -> 对账 -> 校验候选状态 -> 替换状态”的工作区锁。
4. 事实文件通过唯一临时文件、完整写入、关闭和原子发布创建，不覆盖现有唯一 ID。
5. 候选 `state.json` 从锁内重新读取的事实计算，不使用内存中的盲目增量。
6. 候选状态先通过结构和证据一致性校验，再写入同目录唯一临时文件并原子替换。
7. 写入或校验失败时清理己方临时文件，保留原事实和状态。
8. 相同事实重复提交是 no-op，不改变计数和更新时间。
9. 并发提交最终包含两边已经成功发布的事实，不能发生丢失更新。

在符号链接、证据完整性和并发测试全部通过前，不使用真实学生数据。

## 11. 隐私

- 不要求姓名、学校、班级、住址和联系方式。
- 默认不向外部服务发送题目、学生作答、档案或学习记录。
- `student-workspaces/` 必须被 Git 忽略，仓库测试只使用临时虚构数据。
- 只有用户针对明确目的地、目的和最小范围给出当次授权后，才能发送脱敏材料。
- 该 Skill 自身不包含任何需要外部网站才能完成的默认流程。

## 12. 测试策略

### 12.1 Skill TDD 和前向测试

使用相同的真实风格学习请求，先记录没有本 Skill 时的基线行为，再在全新隔离会话
中加载 Skill 验证改善。执行代理只看到原始学生请求和材料，不看到预期答案、评分
规则或已知缺陷。

六科分别至少覆盖：

- 从真实作答识别学科内容薄弱点。
- 区分内容问题和错误模式。
- 单次错误保持 `suspected_gap`。
- 用追问或诊断任务确认薄弱点。
- 生成针对当前薄弱点的最小强化任务。
- 用变式和延迟复测更新掌握状态。
- 不因 Codex 已经讲解而提高状态。

跨学科公共场景覆盖：

- 先尝试和分层提示路径。
- 直接要答案和详细解析路径。
- 解析后的理解检查。
- 清晰及不可读的图片或 PDF。
- 多薄弱点优先级。
- 跨会话恢复和到期复测。
- 临时会话零写入。
- 任何路径都不加载考试政策、访问政策网站或输出政策结论。

### 12.2 自动化和安全测试

- Skill 结构和元数据校验。
- 未完成、错误学科、缺少学生作答或提示级别的证据不能支持状态变化。
- 重复唯一 ID 不重复计数并报告冲突。
- 必需目录、事实和状态的符号链接全部被拒绝。
- 临时目录名称被替换时不能把写入或清理重定向到工作区外。
- 并发创建事实和提交状态不丢失更新。
- 写入失败保留原数据。
- 同一组事实重复对账结果一致。
- 仓库不跟踪学生工作区或真实学生数据。
- Skill 包中不保留考试政策来源、官方网站链接或政策触发规则。

## 13. 验收标准

只有同时满足以下条件，重设计才算完成：

- 核心 Skill 和六科学科参考符合本设计职责。
- 两类薄弱点能够由结构化学生证据区分和持续跟踪。
- 学习引导与直接解析两条路径均通过隔离前向测试。
- 六科均完成“诊断 -> 强化 -> 变式 -> 状态更新”代表性场景。
- 延迟复测可以跨会话恢复，且没有证据时不提高状态。
- 工作区符号链接防护、事实完整性和并发更新测试全部通过。
- Skill 结构校验和全部自动化测试通过。
- 最终独立审查没有未解决的重要问题。
- Git 中不存在真实学生材料、工作区或身份信息。
- Skill 包中不存在考试政策职责或相关网站访问流程。

## 14. 迁移边界

实现本设计时需要从现有 Skill 中删除考试政策参考、触发条件、来源测试和对应前向
场景。已有六科学科参考保留，但要改为包含固定模块、动态知识单元归一化、学科诊断、
强化和迁移验证规则。

现有学生工作区脚本和状态模型需要迁移到结构化事实、派生状态和单一安全提交入口。
迁移只使用虚构测试工作区；没有经过用户明确选择和数据迁移设计，不尝试转换任何
真实学生目录。
