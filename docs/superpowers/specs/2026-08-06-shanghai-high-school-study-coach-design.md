# 上海高中学习教练 Skill 设计

日期：2026-08-06

## 1. 目标

创建一个模块化 Codex skill，为上海高一至高三学生提供完整学习闭环：

```text
诊断 -> 讲解 -> 练习 -> 反馈 -> 沉淀错题
     -> 更新掌握度 -> 调整学习计划
```

该 skill 同时支持通用的上海高中学习需求和基于学生档案的长期个性化辅导。
它必须能够处理文字、图片和 PDF，使用本地文件保存跨会话学习状态，并根据
学生表现自适应反馈，而不是默认立即给出完整答案。

## 2. 范围

### 2.1 学生与年级

- 首版覆盖高一、高二和高三。
- 将年级、学期、教材、课程进度和考试日期作为学生档案属性，不按年级拆 skill。
- 通过不包含个人身份信息的本地学生 ID 支持多个学生。

### 2.2 学科与目标

设置两类学科目标：

1. 高考计分学科：语文、数学、英语、政治、历史、地理。综合优化考试成绩、
   知识掌握、迁移能力和学习过程。
2. 合格考学科：物理、化学、生物。重点关注考纲覆盖、基础题稳定性、薄弱点
   消除和未达标风险。

以上分类来自目标学生画像。不得仅根据该列表推断某位学生的正式选科或当年
考试政策；这些信息必须记录在个人档案中，并以适用的官方文件核实。

### 2.3 分阶段交付

第一阶段实现公共学习闭环和六门高考计分学科，并确定九门学科共同使用的接口
和文件位置。

第二阶段实现物理、化学、生物的合格考模式并完成验证。在第二阶段验收通过前，
skill 不得声称已经完整支持这三门学科。

### 2.4 首版不包含

- 音频、课堂录音、Word 和 Excel 材料处理。
- 数据库、学习管理系统、Notion 或其他云端持久化。
- 自动提交作业或冒充学生完成对外提交。
- 对分数、排名、录取或合格考结果作保证。
- 替代官方课程文件、教师要求或专业教育评估。
- 将完整的受版权保护教材或商业题库复制进 skill。

## 3. 架构决策

首版只创建一个名为 `shanghai-high-school-study-coach` 的模块化 skill。
统一的触发入口可以保持学生状态、学习规划和教学协议一致。学科差异放在按需
加载的参考文件中。

未选择的方案及原因：

- “学习管家 + 多个学科 skills”便于单独发布学科能力，但首版会增加多 skill
  触发、协同和共享状态一致性的复杂度。
- 按诊断、讲解、练习、复盘拆 skills 与学习流程一致，但一次学习会话需要频繁
  跨 skill，且学科规则容易重复或散落。

### 3.1 Skill 目录

```text
skills/
`-- shanghai-high-school-study-coach/
    |-- SKILL.md
    |-- agents/
    |   `-- openai.yaml
    |-- references/
    |   |-- shanghai-curriculum-and-exams.md
    |   |-- chinese.md
    |   |-- mathematics.md
    |   |-- english.md
    |   |-- politics.md
    |   |-- history.md
    |   |-- geography.md
    |   |-- physics-qualification.md
    |   |-- chemistry-qualification.md
    |   `-- biology-qualification.md
    |-- scripts/
    |   |-- init_student.py
    |   |-- validate_student_data.py
    |   `-- summarize_progress.py
    `-- assets/
        `-- student-workspace-template/
```

所有参考文件只放在 `SKILL.md` 下一层。`SKILL.md` 仅保留任务路由、公共
学习闭环、状态更新规则和按条件加载参考文件的说明。

### 3.2 组件职责

`SKILL.md`：

- 识别支持学科的答疑、练习、批改、复盘、规划和进度分析请求。
- 定位或初始化学生工作区。
- 判断当前任务模式并加载相应学科参考。
- 执行自适应教学协议和基于证据的状态更新协议。
- 只读取当前任务所需的最小学生上下文和学科上下文。

`references/`：

- 保存上海课程结构、考试差异、学科教学方法、答题模式和评分依据。
- 标明所有官方规则的适用范围和时效。
- 不重复 `SKILL.md` 中的公共工作流。

`scripts/`：

- 使用模板确定性地初始化学生工作区。
- 校验数据版本、必需文件、JSON 结构和枚举值。
- 根据已有事实生成进度摘要，不执行教学判断。
- 先写临时文件并完成校验，再替换原状态，避免失败写入破坏有效数据。

`assets/`：

- 保存初始化学生工作区时复制的模板。
- 不包含任何真实学生信息。

### 3.3 拆分为独立 Skill 的条件

在满足以下任一条件前，学科能力保持在当前模块化 skill 中：

- 需要与公共核心无关的独立依赖或专用脚本。
- 无法按需加载，学科说明经常挤占当前任务上下文。
- 需要独立的发布和验证周期。
- 离开学习教练和共享学生状态后，仍具有清晰、独立的触发场景。

拆分时必须保留相同的学生数据契约，并迁移而不是复制学科说明。

## 4. 学生工作区

运行时数据存放在 skill 目录之外。默认使用仓库内
`student-workspaces/<student-id>/`，但在创建任何真实工作区前，必须先将
`student-workspaces/` 加入 Git 忽略规则。

```text
student-workspaces/<student-id>/
|-- profile.md
|-- state.json
|-- plans/
|   `-- current.md
|-- mistakes/
|   `-- <subject>.md
|-- sessions/
|   `-- <date>-<subject>-<session-id>.md
`-- materials/
```

### 4.1 文件职责

`profile.md` 是人工可编辑的信息源，保存年级、学期、教材或材料版本、选科、
目标考试、目标日期、必要的学习支持、学习偏好和目标。使用学生代号或不透明 ID；
不要求姓名、学校、班级、住址或联系方式。

`state.json` 是通过脚本校验的当前状态，至少包含：

- `schema_version`、`student_id` 和 `updated_at`。
- 各学科的 `goal_type`、真实测评记录、知识单元状态、证据引用、最近复习时间
  和建议的下次复习时间。
- 根据已完成计划和会话记录计算的过程指标。
- 仅针对合格考学科的未达标风险。

掌握度使用有限等级，避免制造虚假的精确数值：

```text
unassessed -> emerging -> developing -> stable -> transferable
```

高于 `unassessed` 的状态必须引用会话或测评证据。后续证据与原判断冲突时，
掌握度可以下降。

`plans/current.md` 保存当前周计划、优先级、预计投入、完成状态和用于确认完成
的证据。

`mistakes/<subject>.md` 保存尚未解决或近期解决的错题，包括原始来源、错因、
订正、关联知识单元、后续任务和验证结果。经过多次迁移验证的错题应通过有记录的
状态变更归档，不永久占用当前错题列表。

`sessions/` 是追加式证据。每条记录包含任务模式、材料来源、观察结果、使用的
提示、学生回答、结论、状态变化和剩余不确定性。

`materials/` 仅在用户要求保留时保存其材料。一次性答疑不得静默复制外部文件
到该目录。

## 5. 学习流程

一次学习请求按以下步骤执行：

1. 识别学生、学科、任务模式和当前目标。
2. 没有档案时只收集完成当前任务所需的信息；可以先临时答疑，再询问是否创建
   持久化档案。
3. 读取最少量的个人档案、当前计划、相关学科状态和近期证据。
4. 解析文字、图片或 PDF。可能影响答案或评分的识别结果必须先让用户确认。
5. 涉及考试或政策差异时加载 `shanghai-curriculum-and-exams.md`，同时只加载
   当前学科参考文件。
6. 先诊断学生当前思路，再确定讲解深度。
7. 根据自适应反馈协议进行讲解、提示、练习或复盘。
8. 以符合目标和可用时间的有限下一步任务结束。
9. 只有满足证据规则时，才记录会话并更新错题、掌握度和计划。

### 5.1 任务模式

- `assessment`：诊断当前水平或成绩表现背后的原因。
- `explanation`：根据已有证据匹配讲解方式和深度。
- `practice`：提供或完成针对性练习。
- `grading`：根据明确答案或评分标准评估学生作答。
- `review`：复盘已完成的题目、作业或考试。
- `planning`：创建或调整多学科学习计划。

同一会话可以在模式之间切换，但切换过程和引起的状态变化必须在会话记录中可见。

## 6. 自适应教学协议

默认执行以下规则：

- 练习模式下，先查看或询问学生的尝试，再给完整答案。
- 逐层提示：定位卡点、回忆原则、建议下一步，最后才给更完整的示例。
- 学生完成尝试、明确要求完整解析或进入复盘模式后，可以给完整解答。
- 将错因归类为知识缺失、方法薄弱、审题、计算、记忆、表达或推断缺少依据等
  可行动类别。
- 根据已表现出的能力匹配语言和难度，不只依赖学生声明的年级。
- 每次结束只给一个规模适当的后续任务或复习建议，不无限追加练习。

Codex 已经讲解过不能作为提高掌握度的证据。只有学生独立作答、成功订正、延迟
回忆或变式迁移等表现可以支持提升，并且要记录完成过程中获得的帮助。

## 7. 学科适配

### 7.1 语文

要求文本依据、答题层次，并区分合理解释和无依据判断。作文按照任务完成、立意、
结构、证据、语言和修改等明确维度反馈。除非权威评分依据明确要求，不把开放性
阅读或写作题描述成只有一个答案。

### 7.2 数学

检查条件、变形、符号、证明或推导、计算和结果条件。定位第一个有实质影响的
错误，而不只核对最终答案。使用条件变化后的题目验证迁移能力。

### 7.3 英语

区分词汇语法、阅读、以文字材料呈现的听说任务、翻译和写作。修改写作时保留
学生原意，并将表达控制在学生能够理解和复用的水平。分别评价正确性、清晰度、
任务完成和风格，不静默重写全文。

### 7.4 政治、历史、地理

要求材料依据、术语准确、分点组织，以及从证据到结论的明确推理。分别处理政策
概念、时序与因果、地图与空间关系、图表和数据。涉及现实政策或时事时核对发布
日期。

### 7.5 物理、化学、生物

第二阶段以合格考范围覆盖、基础题稳定性和高风险薄弱点为优先目标，不静默提升
到高考难度。题目超出学生配置目标时必须明确说明。

## 8. 资料来源与材料处理

内容冲突时使用以下优先级：

```text
学生当前教材、教师讲义和教师明确要求
> 适用的上海官方课程与考试文件
> 通用学科知识
```

该优先级用于对齐学生当前课堂，不代表高优先级材料一定符合事实。教材或讲义
疑似错误、过期或不适用时，应说明冲突，不能不加判断地重复。

参考文件中每项来自官方来源的规则都要记录发布机构、标题、发布日期或更新日期、
获取日期、URL 或文档标识，以及适用范围。过期或未验证的信息必须标注。不得编造
政策、评分标准、分数换算、题目出处或学生成绩。

处理图片和 PDF 时：

- 尽量保留页码和题号边界。
- 明确标记无法识别的文字、图形、公式和答题痕迹。
- 不确定内容可能改变答案或评分时，要求更清晰的局部图片或用户确认。
- 不根据不可靠的识别文本更新掌握度或批改结果。

## 9. 指标与规划

使用综合学习效果模型。

高考计分学科考虑：

- 真实考试或测评成绩及趋势，不生成模型猜测分数。
- 知识单元掌握度和迁移证据。
- 错误是否重复出现，以及延迟复习是否成功。
- 计划完成情况和练习稳定性。

合格考学科考虑：

- 基于适用官方范围的覆盖情况。
- 基础题表现稳定性。
- 尚未解决的高风险知识单元。
- 带有证据和不确定性说明的定性未达标风险。

学习计划不能只优化刷题数量。它要在保障六门高考计分学科深度的同时，为合格考
风险消除保留必要时间。

## 10. 容错与隐私

### 10.1 容错

- 缺少档案：使用最小临时上下文完成当前任务，然后提供初始化选项。
- 材料不可读：停止评分和状态更新，要求更清晰的输入。
- 状态无效：先校验并保留原文件，报告具体错误，不直接覆盖。
- 会话中断：可以保存未完成会话，但不能因此提高掌握度。
- 来源冲突：记录双方内容、来源、适用性和选择当前工作假设的理由。
- 缺少权威答案或评分标准：区分确定反馈和不确定评分，不编造精确分数。

### 10.2 隐私

- 使用学生代号或不透明 ID，只收集与学习相关的属性。
- 创建真实数据前将 `student-workspaces/` 加入 Git 忽略规则。
- 仓库测试只使用虚构和脱敏数据。
- 未经明确授权，不把学生材料发送到外部服务。
- 任何可能公开或提交学生数据的操作都要事先警告。

## 11. 验证策略

### 11.1 结构验证

- 使用官方 skill 校验器检查 skill 目录。
- 确认 frontmatter 只包含 `name` 和 `description`，且 description 覆盖全部
  目标触发场景。
- 确认 `agents/openai.yaml` 与实际 skill 一致。
- 确认 `SKILL.md` 直接指向每个条件加载的参考文件。

### 11.2 脚本测试

- 从空目录初始化工作区，并重复初始化，确认不会破坏已有数据。
- 拒绝未知数据版本、错误 JSON、缺少证据引用和非法掌握度。
- 确认写入失败时保留上一个有效状态。
- 确认进度摘要只根据已有记录生成。

### 11.3 行为回归用例

使用虚构数据测试至少以下场景：

1. 初始化一名高一学生并创建平衡的周计划。
2. 分析数学试卷 PDF，定位第一个实质错误，逐层提示，执行变式验证，并根据证据
   更新状态。
3. 复盘英语作文图片，保留原意、解释修改并生成针对性练习。
4. 使用各自的证据和答题规则处理语文、政治、历史和地理材料题。
5. 根据六门高考计分学科趋势调整计划，同时保留合格考风险学科时间。
6. 拒绝对不可读图片或无法确认的公式作精确评分。
7. 明确展示教师材料与官方来源的冲突。
8. 学生没有独立表现时，不提高掌握度。
9. 确认真正的学生工作区和材料没有被 Git 跟踪。

第二阶段为每门合格考学科增加诊断、练习、复盘和跨学科规划用例。

### 11.4 前向测试

在相互隔离的新 Codex 会话中使用真实风格的请求，使测试结果依赖 skill 而不是
已有对话。测试输入只包含待测 skill、虚构原始材料和用户请求，不透露预期答案
或设计结论。评估触发、参考文件选择、教学行为、状态安全和输出实用性。

## 12. 验收标准

第一阶段只有满足以下条件才算完成：

- 一个已安装 skill 能稳定触发支持学科的答疑、练习、批改、复盘、规划和进度
  分析任务。
- 能跨会话维护一致的本地学生档案，且不读取无关学生或无关学科数据。
- 正确执行来源优先级，并展示材料识别不确定性或来源冲突。
- 练习模式默认逐层提示，只在协议允许的情况下提供完整答案。
- 六门高考计分学科均有代表性用例并通过。
- 没有学生表现证据时绝不提高掌握度。
- 结构校验、全部脚本测试和第一阶段行为回归测试通过。
- Git 中没有真实学生工作区、作业、成绩或身份信息。

第二阶段只有在三门合格考学科适配及新增行为用例通过，并完成九科综合规划回归
测试后才算完成。

## 13. 触发示例

- “为学生 A 建立高一学习档案，并根据当前目标制定本周计划。”
- “分析这份数学试卷，先找出错因，不要马上给完整答案。”
- “批改这张英语作文图片，保留原意并安排下一轮练习。”
- “根据本月六科成绩和错题记录调整学习计划。”
- “评估生物合格考的未达标风险。”
- “解释这道历史材料题，并把本次表现记录到学生档案。”

小学、初中、非上海考试体系、大学课程或无关的一般知识请求，不应仅因为提到
“学习”就触发该 skill。
